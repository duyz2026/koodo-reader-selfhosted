# Koodo Reader 自建服务器多端同步阅读系统 — 需求与总体框架

> 版本：v0.1（草案） 日期：2026-08-28
> 服务器：Ubuntu（已部署完毕，具备 Docker 能力或可安装）

---

## 1. 项目目标

在自己掌控的服务器上建立**统一阅读数据中枢**，实现：

- **阶段一（本期）**：2 台电脑端 + 1 台手机端的阅读数据同步
  - 同步范围：书架/图书库、阅读进度、书签、高亮、笔记
- **阶段二（下期）**：平板端接入 + Kindle 同步阅读

核心诉求：数据私有化（不依赖第三方云盘）、多端无缝续读。

**附加目标（2026-08-28 新增）**：整套方案开源化，上传 GitHub 成为可共享、可升级、可复用的开源软件——详见 `02-开源化与GitHub项目规划.md`，私有部署里程碑与开源版本迭代同源推进。

## 2. 关键技术事实（调研结论，方案设计的前提）

1. **重要更正（2026-08-30 实测）：Koodo Reader 的 Docker / WebDAV 等云端同步均为专业版功能**。官方定价（中文站）：免费版 ￥0，专业版 ￥25/年（限时年付）。
   - **免费版不支持任何官方跨平台同步**。官方说明：免费版仅支持桌面端（Windows/macOS/Linux）之间借助第三方同步工具同步数据；移动端最多 20 本书；「发送到 Kindle」亦为专业版功能。
   - **路径 A — 官方 Docker 镜像 + 数据源功能（本项目采用）**：官方镜像 `ghcr.io/koodo-reader/koodo-reader:master` 设置 `ENABLE_HTTP_SERVER=true` 后，客户端在「数据源」中选择 **Docker**，填写服务器地址 + 账号密码，即可将阅读数据同步到自建服务器。网页版走 80 端口，数据源功能走 8080 端口。**需专业版账号。**
   - **路径 B — WebDAV**：服务器上跑任意 WebDAV 服务（推荐 SFTPGo），客户端配置 WebDAV 地址。**同样需专业版账号。**
   - **免费用户替代路径**：桌面端选「本地文件夹」作数据源，配合 Syncthing 等工具同步；但移动端不支持（官方标注"敬请期待"）。
   - 其余云盘（OneDrive/百度网盘等）不满足"自有服务器"要求，排除。
2. **同步为增量合并**（官方原文：每次只同步变化的数据，已传输过的图书不会重复传输）。官方有一套数据比对算法，会自动分析本地与云端差异——上传本地变更、下载云端缺失或需更新的内容，最终本地与云端各保存一份合并后的数据。**任何设备都可以作为上传端，不限于一台。**
   操作纪律：在某台设备产生变更后，先在该设备点同步，再在其他设备依次点同步；避免多台设备离线状态下同时修改同一条笔记（合并算法可能无法裁决）。
3. **Kindle 官方固件无法运行 Koodo Reader**（封闭系统、仅 AZW3/MOBI/EPUB 新格式），阶段二的"Kindle 同步"只能做折中方案（见 §6）。
4. Docker 部署的网页版数据默认存浏览器缓存，官方建议 **HTTPS 访问 + 数据源/本地存储**，这决定了必须上反代和证书。

## 3. 总体架构（阶段一）

```
┌──────────────────────┐
│  客户端（4 类设备）    │
│  PC-1 / PC-2（桌面版）│
│  手机（iOS/Android）  │
│  [阶段二] 平板/Kindle │
└──────────┬───────────┘
           │ HTTPS（443）
┌──────────▼───────────┐
│  Nginx / Caddy 反代   │ ← 公网 IP 直连，自签证书/后续补域名
│  + 访问控制 + 日志    │
└──────────┬───────────┘
┌──────────▼───────────────────────────┐
│  Ubuntu 服务器                        │
│  Docker Compose：                     │
│   ├─ koodo-reader（网页版 :80）        │
│   │    ENABLE_HTTP_SERVER=true        │
│   │    数据源服务（:8080，仅内网暴露） │
│   └─ [可选] SFTPGo（WebDAV，路径B备用）│
│  存储：/srv/koodo/uploads（数据卷）    │
│  备份：cron 每日打包 → /srv/backup    │
└──────────────────────────────────────┘
```

**方案选型建议：路径 A（Docker 数据源）为主，理由**：
- 官方原生支持，客户端配置最简单（选 Docker 数据源即可）
- 顺带免费获得网页版，平板阶段可直接用浏览器访问网页版，零成本过渡
- 路径 B（SFTPGo + WebDAV）作为备选，在路径 A 出现兼容问题或需要更细的用户/权限管理时启用

## 4. 功能需求（阶段一）

| 编号 | 需求 | 说明 | 优先级 |
|------|------|------|--------|
| FR-1 | 服务端部署 | Ubuntu + Docker Compose 部署 Koodo 官方镜像，开启数据源功能（8080） | P0 |
| FR-2 | HTTPS 接入 | 已确认：**有公网 IP、暂无域名**。方案：公网 IP + 自签证书（客户端信任一次）或 DDNS 免费域名 + Let's Encrypt；后续注册域名后平滑切换 | P0 |
| FR-3 | 账号与认证 | 设置强口令 `SERVER_USERNAME/SERVER_PASSWORD`，杜绝默认密码公网暴露 | P0 |
| FR-4 | 三端同步 | 2 台 PC（Windows/macOS 桌面版）+ 手机端，配置同一数据源，验证：进度、书签、高亮、笔记、书架一致 | P0 |
| FR-5 | 图书导入与分发 | 书籍文件统一从服务端/主设备导入，其他端同步获取 | P1 |
| FR-6 | 数据备份 | cron 每日备份 uploads 数据卷到独立目录，保留 N 天；支持手动全量导出 zip | P1 |
| FR-7 | 安全加固 | 防火墙仅放行 443；8080 数据源端口不直接暴露公网（走反代路径或仅内网）；fail2ban 可选 | P0 |
| FR-8 | 服务可观测 | 容器 restart:always；部署简单状态页/健康检查脚本 | P2 |
| FR-9 | 恢复演练 | 验证"服务器数据丢失后，从备份完整恢复书库与进度"的流程 | P1 |

## 5. 非功能需求

- **安全**：全程 TLS；账号密码强复杂度；同步数据不出自有服务器
- **性能**：单用户场景，书库 ≤ 数千本，无并发压力；重点保证手机弱网下备份包可传输（数据包可能较大，需关注）
- **可靠性**：服务重启自动拉起；备份异地/异盘一份
- **可维护性**：全部服务容器化，docker-compose.yml + .env 纳入版本管理；编写部署/恢复手册

## 6. 阶段二预研（平板 + Kindle）

| 设备 | 方案 | 可行性 |
|------|------|--------|
| 平板（iPad/Android pad） | ① 安装 Koodo 移动版，配置同一数据源（与手机一致）② 直接浏览器访问服务器网页版 | 高，基本零额外成本 |
| Kindle | 方案 1：**Send to Kindle / 邮件推送**——服务器或 Calibre-web 管理书库，推送 AZW3/EPUB 到 Kindle；进度无法回流，属"单向分发" | 中（只解决"书到 Kindle"，不解决"同步"） |
| Kindle | 方案 2：**KOReader**（需越狱）——KOReader 支持自建 sync 服务器（kosync），可在 Kindle 上续读 PC 端位置；但无法与 Koodo 的笔记体系互通 | 中低（体验割裂，需评估越狱风险） |
| Kindle | 方案 3：接受"Kindle 仅作补充阅读设备"，以人工导出笔记/手动标记进度对齐 | 低成本兜底 |

**建议**：阶段二先落地平板（顺带完成）；Kindle 部分先做方案 1（书库分发），同步阅读作为长期目标观察 Koodo 官方与 KOReader 的进展再定。

## 8. 风险与待确认项

| 风险 | 影响 | 对策 |
|------|------|------|
| 多端离线同时修改同一内容 | 合并算法可能无法裁决，某端改动丢失 | 改完即同步；避免多端离线同时改同一条笔记；重要笔记本地留档 |
| 首次同步数据量大 | 手机弱网首次同步慢/失败 | 首次同步在 WiFi 下完成，之后均为增量 |
| 无域名/无公网 IP | HTTPS 与外网访问受限 | DDNS 或 Tailscale 内网穿透备选 |
| Kindle 封闭生态 | "真同步"短期无解 | 见 §6 折中方案 |

**已确认事项（2026-08-28）**：
1. **网络**：服务器有公网 IP、暂无域名 → HTTPS 走自签证书或 DDNS + Let's Encrypt，后续可切正式域名。
2. **设备**：苹果 + 安卓混用 → iPhone/iPad 与安卓设备均安装 Koodo 移动版/桌面版，客户端配置方式一致。
3. **Kindle**：阶段二待平板接入后再定方案（推送分发 / KOReader / 兜底）。
4. **里程碑调整**：M1 部署时同步产出自签证书或 DDNS 的 TLS 方案说明。
