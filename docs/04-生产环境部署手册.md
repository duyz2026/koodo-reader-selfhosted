# 生产环境部署手册（v0.1 实机验证）

> 日期：2026-08-29 适用：`install.sh` v0.1
> 目标：在你的 Ubuntu 生产服务器上跑通部署，验证通过后拍快照冻结，再上 GitHub。

---

## 0. 结论先行：三步 + 一个最大风险

```bash
# 1) 把代码传到服务器（在你电脑上执行，Git Bash）
# 2) 服务器上执行安装
sudo bash install.sh
# 3) 验证
```

**最大风险（必须先决策）：手机端证书信任问题**

你的服务器**有公网 IP、无域名**。若用自签证书（TLS 模式 2）：

| 客户端 | 自签证书表现 |
|--------|--------------|
| 桌面版 Koodo（Windows/macOS） | 通常可连（可能会警告） |
| **安卓 Koodo** | 大概率报证书不受信任，连接失败 |
| **iPhone Koodo** | iOS 对自签证书限制严格，需要先在手机装描述文件并手动信任 |

**强烈建议（成本几乎为零）**：领一个免费域名 + Caddy 自动申请 Let's Encrypt 证书。

- 推荐 <https://www.duckdns.org>（免费、无需信用卡、支持 API 更新 IP）
- 或腾讯云/阿里云买个 `.top`/`.xyz` 域名，几块钱一年，解析到你的公网 IP
- 之后 `install.sh` 选 **TLS 模式 1（域名 + Let's Encrypt）**，一劳永逸解决手机端信任问题

若坚持用公网 IP：先按模式 2 部署，手机端连不上时再按 §7 的方案 B 处理。

## 1. 前置条件检查（服务器上执行）

```bash
# 系统版本（需 Ubuntu 20.04+ 或 Debian 11+）
cat /etc/os-release | head -3

# Docker 与 compose v2
docker --version
docker compose version          # 必须输出 v2.x，不是 docker-compose 1.x

# Docker 守护进程
docker info >/dev/null && echo "docker OK"

# 端口占用（若 80/443 被 openresty/nginx/宝塔 占用，安装时可改端口）
ss -tlnp | grep -E ':(80|443)\s'

# 磁盘与内存
df -h /srv 2>/dev/null || df -h /
free -h
```

若 80/443 被占用（如 openresty），**不需要停它**：安装时把 HTTP 端口改成 `8090`（或任意空闲端口），Caddy 只监听这个端口。Tailscale/内网场景推荐这样做，完全不影响现有服务。

**防火墙**：放行你实际使用的端口（示例用 8090）。
```bash
ufw allow 8090/tcp
ufw status
```

## 3. 执行安装

```bash
ssh root@100.86.58.36
cd /opt/koodo-sync-hub
sudo bash install.sh
```

交互项填法：

| 提示 | 有域名（推荐） | 公网 IP / Tailscale（当前场景） |
|------|----------------|--------------------------------|
| 访问地址 | `your.duckdns.org` | Tailscale 机器名如 `ibm-t460-dyz`，或 IP `100.86.58.36` |
| TLS 模式 | `1` | `3`（纯 HTTP，Tailscale 隧道已加密） |
| HTTP 端口（网页版） | 回车默认 `80` | 若 80 被占用，填 `8090` |
| 数据源端口 | 回车默认 `8091` | 回车默认 `8091`，不能与网页版端口相同 |
| Let's Encrypt 邮箱 | 你的邮箱（仅模式 1 需要） | — |
| 管理员用户名 | 回车用 `admin` | 回车用 `admin` |
| 数据目录 | 回车用 `/srv/koodo/uploads` | 同左 |

安装完成会打印（示例）：
```
网页版:   http://ibm-t460-dyz:8090/
数据源:   http://ibm-t460-dyz:8091   ← Koodo 客户端填这个
账号:     admin
密码:     xxxxxxxxxxxxxxxx           ← 务必记下来
```

> **为什么数据源用独立端口**：早期版本把数据源挂在 `/datasource` 子路径下与网页版共用端口，
> 但实测发现**安卓端不接受路径前缀**，只认官方示例的 `host:port` 格式（桌面版能接受子路径）。
> 因此改为端口职责分离：网页版用 HTTP_PORT，数据源用 DS_PORT（默认 8091），全平台统一。

> 内部细节：`install.sh` 会根据模式自动选择 `docker-compose.http.yml`（模式 3，不绑 443）或 `docker-compose.tls.yml`（模式 1/2），并把 `COMPOSE_FILES` 写进 `.env`。`koodo-hub` 会读取这个变量，所以你日常运维不需要记 compose 文件组合。

## 4. 验证清单（逐条确认）

```bash
cd /opt/koodo-sync-hub

# (1) 两个容器都 Up
docker compose ps
# 期望：koodo-sync-hub-koodo-1  Up / koodo-sync-hub-caddy-1  Up

# (2) 网页版可访问（模式 3 不用 -k，模式 2 用 -k）
curl -o /dev/null -w "HTTP %{http_code}\n" http://ibm-t460-dyz:8090/

# (3) 数据源连通（带账号密码，期望非 401/000）
curl -u admin:<密码> -o /dev/null -w "HTTP %{http_code}\n" http://ibm-t460-dyz:8091/

# (4) 看 Koodo 日志，确认数据源服务已监听 8080
docker compose logs koodo --tail 50

# (5) 看 Caddy 日志（代理错误都在这）
docker compose logs caddy --tail 50

# (6) 运维 CLI 状态
./koodo-hub status
```

**判定标准**：(1) 双 Up、(2) 返回 200、(3) 返回非 401/000。(3) 若返回 404 也算连通（说明反代到了 8080，只是路径不存在），可继续测客户端。

## 5. 客户端配置

Koodo Reader 桌面版 / 手机版 → 设置 → 数据源（或在"同步与备份"里）→ 选 **Docker**：

- 服务器地址：`http://your.host:8091`（**不要加任何路径后缀**）
- 用户名：`admin`
- 密码：安装时打印的那个

先在 **1 台 PC** 上配置并导入几本书，**在该 PC 上点一次同步**把书上传到数据源，
再在第二台 PC / 手机上登录同一数据源并同步，检查书架与进度是否同步过来。

> 手机端若书架为空：确认已开启「自动下载云端图书」，或手动点「导入云端图书」。
> 书籍文件走你自己的 Docker 数据源，阅读进度/笔记/高亮走 Koodo 官方云端——这是 Koodo Pro 的机制。

## 6. 同步规约（务必遵守）

Koodo 官方同步为**增量合并**：每次只同步变化的数据，已传输过的图书不会重复传输。系统会自动分析本地与云端差异，上传本地变更、下载云端缺失或需更新的内容，最终本地与云端各保存一份合并后的数据。**任何设备都可以作为上传端，不限于一台。**

> **操作纪律**：在某台设备产生变更（导入书、加书签、写笔记）后，**先在该设备点同步**，再在其他设备**依次点同步**。
> **注意**：Docker / WebDAV 等云端同步均为**专业版功能**（￥25/年），免费版不支持。

## 7. 端口职责说明

`install.sh` 生成的 Caddyfile 有两个站点块，职责完全分离：

| 容器内端口 | 对外端口 | 上游 | 用途 |
|-----------|---------|------|------|
| 80 | `HTTP_PORT`（默认 80/8090） | `koodo:80` | 网页版（浏览器访问） |
| `DS_PORT` | `DS_PORT`（默认 8091） | `koodo:8080` | 数据源（所有客户端） |

示例（TLS 模式 3）：

```
:80 {
  encode gzip
  reverse_proxy koodo:80
}

:8091 {
  encode gzip
  reverse_proxy koodo:8080
}
```

**不要**再给数据源加 `/datasource` 之类的路径前缀——安卓端不认。

若需修改数据源端口，改 `.env` 里的 `DS_PORT` 后重建：

```bash
sed -i 's/^DS_PORT=.*/DS_PORT=新端口/' .env
docker compose -f docker-compose.yml -f docker-compose.http.yml up -d
```

## 8. 失败回滚 / 重装

```bash
cd /opt/koodo-sync-hub
docker compose down          # 停服务（数据卷保留）
rm -f .env                   # install.sh 要求无 .env 才能重装
sudo bash install.sh         # 重新走向导
```

彻底重来（**会删数据**）：
```bash
docker compose down -v
rm -rf /srv/koodo/uploads
rm -f .env
```

## 9. 部署成功后：立刻拍快照

```bash
cd /opt/koodo-sync-hub
./koodo-hub backup              # 先备份
./koodo-hub freeze              # 冻结：写 koodo-image.lock（digest）+ 置 FREEZE=1
./koodo-hub status              # 确认为冻结态
cat koodo-image.lock            # 记录 digest
```

## 10. 排查速查表

| 现象 | 原因 | 处理 |
|------|------|------|
| Caddy 启动失败 | 80/443 被占用 | `ss -tlnp` 查占用者，停掉或换端口 |
| 证书申请失败（模式 1） | 域名未解析到本机 IP / 80 端口不通 | 确认 DNS 解析；确认防火墙放行 80 |
| 手机端提示证书不受信任 | 自签证书 | 换免费域名 + Let's Encrypt（推荐），或手机装证书 |
| 客户端连不上数据源 | 路径前缀不兼容 | 按 §7 改独立端口 |
| 数据源返回 401 | 账号密码填错 | 用 `curl -u` 复测；`.env` 里核对 |
| `docker compose` 命令不存在 | 只有旧版 docker-compose | 安装 Docker 官方 compose v2 插件 |
| 同步后某端改动丢失 | 多端离线同时修改同一内容 | 避免同时改；定期 `koodo-hub backup`，必要时从备份恢复 |
| 客户端显示数据源为 Pro 功能无法绑定 | 未登录专业版账号 | Docker/WebDAV 同步需专业版（￥25/年），先试用 7 天 |
