# 阶段二准备纪要：iPad 与 Kindle 接入

> 记录时间：2026-09-01
> 适用版本：当前主线 v1.0.0（已冻结）｜本纪要属于 **2.0 的前期调研**，不改变 v1.0.0 的行为
> 状态：**调研完成，待真机验证（公网可达性未确认）**

---

## 一、起因：iPad 装不上 Tailscale

准备给 iPad 接入 Koodo 时发现：**国区 App Store 搜不到 Tailscale**（iOS/iPadOS 需外区 Apple ID 才能下载）。

顺着查下去，发现一个比"装不上"更严重的事实：

> **Tailscale 的网络在国内部分被禁**，即使通过外区 ID 装上，从国内连也常走中继，可能连不上或极慢。

这直接动摇了 v1.0.0 的一个隐含假设——**"所有设备靠 Tailscale 组虚拟局域网"**。

## 二、结论：国内设备不应把 Tailscale 当作必经路径

| | 说明 |
|---|---|
| **影响设备** | iPad（无法安装）、任何不愿/不能装 VPN 的设备 |
| **影响程度** | 不装 Tailscale → 连不上 `ibm-t460-dyz:8091` → 只有书名和进度（官方云同步），**拿不到书文件和封面** |
| **根因** | 不是 Koodo 的问题，是"数据源地址只有 Tailscale 内能解析"这个拓扑限制 |

## 三、决策：B 方案 —— 公网直连 + HTTPS

**核心思路**：服务器本就有公网 IP，直接把它暴露给互联网，所有设备填同一个 URL，不依赖任何 VPN、不依赖 App Store。

| 对比项 | A. 外区 ID 装 Tailscale | **B. 公网直连（已选）** |
|---|---|---|
| iPad 体验 | 要装 VPN App，国内连接不稳 | 直接填 URL，零 App |
| 依赖 | Tailscale 境外服务器 | 只依赖自家服务器 |
| 速度 | 绕境外，慢 | 国内直连，更快更稳 |
| 顺带收益 | 无 | 一并解决"没装 Tailscale 的手机只有骨架"问题 |
| 代价 | 低 | 需域名；数据源对公网可见 |

**用户已确认：B 方案，且暂不购买域名，先验证连通性。**

## 四、一个重要澄清：跨网络不是障碍

用户提出"服务器和 iPad 不在同一个网络"——**这恰恰是公网直连要解决的场景，不构成问题**：

- Tailscale 的作用是「把不同网络的设备拉进同一个虚拟局域网」；
- 公网直连则根本不要求同网，iPad 走普通互联网敲服务器公网 IP 即可，物理位置在哪都无所谓。

**真正的障碍只有一个：那个公网 IP 是不是「真公网」。**

## 五、前置风险：CGNAT（未验证）

很多家庭宽带给的是**运营商级 NAT（CGNAT）**：

- 外网看到的 IP 是运营商出口共享的；
- 在路由器上做端口转发**完全无效**，外界敲不到你家；
- 典型特征：路由器 WAN 口 IP 为 `100.64.x.x`，或与 `curl ifconfig.me` 结果不一致。

**这一步不先验证，后面所有配置都是白做。**

### 判定方法（服务器上执行）

```bash
echo "外网看到的IP:"; curl -s ifconfig.me; echo; echo "服务器网卡IP:"; ip -4 addr show scope global | grep inet
```

| 结果 | 判断 | 下一步 |
|---|---|---|
| 两个 IP 一致 | 真公网直给服务器 | 开防火墙 8091 即可 |
| 网卡是 `192.168.x` / `10.x` | 服务器在路由器后 | 需端口转发；**必须再看路由器 WAN 口 IP** |
| WAN 口是 `100.64.x.x` | **CGNAT，公网直连不通** | 转备选方案 |
| WAN 口 IP == `ifconfig.me` | 真公网，可行 | 端口转发 + 开防火墙 |

> 输出里 `tailscale0` 那行（100 开头）是虚拟网卡，忽略。

## 六、若确为 CGNAT 的备选路径（按优先级）

1. **宽带公网 IPv6** —— 很多家宽已下发 IPv6，iPad 蜂窝网一般也支持。零成本、直连不绕路，最干净。
2. **EasyTier** —— 国产开源组网工具，国内有中继节点、可自建，直接替代 Tailscale。
3. **内网穿透** —— cpolar / natapp（国内服务，有免费额度）；若有 VPS 可用 frp 自建。
4. **Cloudflare Tunnel** —— 免费，但国内速度一般，放最后。

## 七、分阶段推进计划

**阶段一（当前，零成本验证）**

- 只开放 **8091 数据源端口**给公网，用 `http://<公网IP>:8091` 让 iPad 连接
- **8090 网页版暂不开**，继续只走 Tailscale —— 暴露面最小
- 验证 iPad 能刷出书、能下载阅读

**阶段二（验证通过后）**

- 上域名（或免费 DDNS 主机名）+ Let's Encrypt 证书，改为 `https://`
- 解决两个遗留问题：① HTTP 明文 → 加密；② 动态 IP 会变 → 固定名字

> ⚠️ **阶段一的临时妥协**：无域名拿不到受信任证书（Let's Encrypt 不给裸 IP 发证），所以阶段一是 HTTP 明文。这是验证期的临时态，非最终形态。介意的话阶段一只在家用 WiFi 下测，不外带。

## 八、v1.0.0 与 2.0 的关系

| 版本 | 连接方式 | 状态 |

## 十、附：本次调研的三个关键认知

1. **Tailscale 在国内不可靠** —— 不只是"国区商店没有"，更是网络层面部分被禁。国内设备不应依赖它。
2. **跨网络从来不是问题** —— 公网直连本就跨网络；真正的前置条件是「真公网 IP 而非 CGNAT」。
3. **Koodo 的两条通道分工（再次印证）** —— 官方云只同步书名/进度/笔记/评论；书文件和封面 100% 走自建数据源。没连上数据源的设备，就只有"骨架没有肉"。
