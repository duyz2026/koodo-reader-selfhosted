## 1. ✅ 已掌握（不用我再手把手）

### 1.1 Koodo 客户端操作（PC / 安卓 / iPad）

- [ ] 在 Koodo 里**添加 Docker 数据源**，填地址 / 用户名 / 密码
- [ ] 理解数据源三件套填什么：地址 `http://主机:8091`、用户名 `SERVER_USERNAME`（默认 admin）、密码 `SERVER_PASSWORD`
- [ ] 点**同步**把本地书上传到自建数据源
- [ ] 在另一台设备点**「导入云端图书」**把书拉下来
- [ ] 知道**上传端先同步、其他端再依次同步**的先后顺序纪律
- [ ] 开通并管理 **Koodo Pro**（￥25/年，Pro 才能用 Docker 数据源）
- [ ] 区分两件事：**书和封面走自建数据源**，**进度/笔记/书签走 Koodo 官方云**

### 1.2 服务器上跑诊断命令（有截图为证）

你亲手在服务器终端跑过并回传了结果：

- [ ] `curl ifconfig.me` — 查外网 IP
- [ ] `ip -6 addr` — 查网卡 IPv6 地址
- [ ] `ss -tlnp` — 查端口监听状态
- [ ] `ufw status` — 查防火墙放行规则
- [ ] `curl -6 http://[IPv6]:8091` — 验证服务是否通（返回 401 即正常）

### 1.3 GitHub 发布链路（你亲手打通的关键一步）

- [ ] 用 `winget install --id GitHub.cli` 装命令行工具
- [ ] 执行 `gh auth login`，在浏览器里完成 GitHub 授权登录
- [ ] 用 `gh auth status` 确认登录状态
- [ ] 理解"**我授权、AI 代跑**"这个分工模式，并接受它

### 1.4 网络与应用排查

- [ ] 用 `test-ipv6.com` 判断一台设备的 IPv6 连通性（iPad 上跑出 10/10）
- [ ] 在安卓手机上装 Tailscale 并登录组网
- [ ] 判断"网页打不开"时先怀疑**防火墙/网络层**，而不是先怀疑应用配置

### 1.5 决策与产品判断（这是你的强项，不是我的）

- [ ] 在多个方案里做取舍（选 B 方案公网直连、暂不买域名）
- [ ] 判断暴露面大小、接受"阶段一用 HTTP 明文过渡"这种权衡
- [ ] 公众号写作：前 4 期已独立完成并发布
- [ ] 识别真实需求边界（如"移动硬盘的书全导入后必须离站备份"）

## 3. ⬜ 还没碰过 / 做过但失败（下一阶段要攻的）

按**重要性 × 紧急度**排序，这是 2.0 阶段的学习路线。

### P0 — 卡住 iPad 接入的两个拦路虎

| # | 技能 | 为什么卡这 | 学成标准 |
| --- | --- | --- | --- |
| 1 | **登录光猫后台，放行 IPv6 入站 8091** | iPad 两个浏览器都打不开 8091，根因就是光猫 IPv6 防火墙拦截。不解决这个，后面全白搭 | 自己能进光猫后台找到 IPv6 防火墙/安全设置并放行端口 |
| 2 | **在 Koodo 里删掉旧数据源、重新添加** | iPad 的数据源地址是从安卓经官方云同步来的 Tailscale 域名，iPad 解析不了，且界面不带地址编辑框 | 会走"移除 → 重新添加 → 填 IPv6 地址 → 开自动下载"这一串 |

### P1 — 让方案脱离"临时态"

| # | 技能 | 说明 |
| --- | --- | --- |
| 3 | **从 X1 用 SSH 连上服务器** | 目前**一直连不上**（密码被拒 / 直连超时），所以服务器操作只能靠你在机房本机敲。搞定 SSH 能省掉大量跑腿 |
| 4 | **买域名 + 配 DDNS** | 服务器 IPv6 是 `dynamic`（动态），会变。不上 DDNS，过几天地址失效又要重配所有设备 |
| 5 | **申请 Let's Encrypt 证书、改成 HTTPS** | 无域名就拿不到受信任证书。这是阶段二的核心目标，也是公网暴露的安全底线 |
| 6 | **配置 `ALLOWED_ORIGINS`** | 公网一暴露就要限制请求来源，防止被扫 |

### P2 — 工程化与可靠性

| # | 技能 | 说明 |
| --- | --- | --- |
| 7 | **restore 恢复演练** | 只做过 backup，**从没验证过能恢复**。没演练过的备份等于没备份 |
| 8 | **cron 自动备份** | 目前备份全靠手动，忘了就没了 |
| 9 | **`koodo-hub upgrade` 实测** | 升级路径写了但从没真跑过，不知道会不会翻车 |
| 10 | **Kindle / KOReader 接入** | 好消息：官方镜像内置 KOReader 服务（`ENABLE_KOREADER_SERVER=true`，端口 7200），不用自建 kosync |
| 11 | **OPDS 使用** | `ENABLE_OPDS=true` 开启，地址「数据源地址 + /opds」，给第三方阅读器取书用 |

### P3 — 发布工程化（让项目更像"正经开源作品"）

| # | 技能 | 说明 |
| --- | --- | --- |
| 12 | **git 命令行日常操作** | 目前 commit / tag / push 全是我代跑，你自己不敲 |
| 13 | **GitHub 网页端操作** | Release 是我用 gh 发的，你只做了授权 |
| 14 | **一键安装脚本 `curl | bash`** | 让陌生人一条命令装上，是推广转化率的关键 |
| 15 | **CI 自动发版** | 打 tag → 自动出 Release notes，杜绝"人忘了锁 digest" |

## 4. 一个诚实的提醒：备份没演练过

清单里第 7 项值得单独拎出来说。

我们现在的状态是：

- ✅ 做过备份（`backups/koodo-20260830-072557.tar.gz`）
- ❌ **从没恢复过**

备份这东西，**能恢复才叫备份，不能恢复只是一个占空间的文件**。
建议在动光猫、动 IPv6、动任何配置之前，先花 10 分钟做一次恢复演练——
在一个临时目录里解开备份包，确认书文件、封面、配置文件都在且完整。

这比学任何新技能都优先。

## 5. 下一步学习顺序建议

```
第 0 步  恢复演练（10 分钟，先确认后路）
   ↓
第 1 步  光猫放行 IPv6 8091  →  iPad 浏览器能打开  →  iPad Koodo 重配数据源
   ↓                                    （到这一步，iPad 就通了）
第 2 步  搞定 SSH（可选但强烈建议，省掉无数跑腿）
   ↓
第 3 步  买域名 + DDNS + HTTPS  →  方案从"能用"变成"能长期用"
   ↓
第 4 步  Kindle / KOReader（阶段二收尾）
   ↓
第 5 步  发布工程化：一键安装脚本 + CI
```

**节奏建议**：跟 v1.0 一样，**一次只攻一个**。每攻下一个就更新这份清单，
看到 ✅ 越来越多，比看任何进度表都直观。
